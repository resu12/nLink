# nLink 0.4.1

0.4.1 is a hardening release for the existing remote-help flow introduced in 0.4.0. It focuses on stabilization, security hardening, performance cleanup, installer reliability, and clearer session/control behavior. No new product area was added in this release.

## Highlights

- Remote control is more reliable across control start, stop, disconnect, reconnect, and session end.
- Helper and helpee UI clear stale control/session state faster and explain important transitions more clearly.
- Installer, portable packaging, and bundled NKN bridge handling are more robust for real upgrades and shutdown.

## Included improvements

- Tighter request- and session-scoped remote-control handling to reduce stale work crossing reset, reconnect, or control restart.
- Better helper remote-control recovery when pointer mapping is temporarily unavailable, with mapping restored when active control starts.
- Coalesced replaceable control-state snapshots so they do not crowd out key/button input under load.
- Earlier suppression of stale display-info sends during stop/reset/restart churn.
- Clearer status wording for approval wait, authorization loss, screen-change/mapping loss, and remote-ended sessions.
- Removed stale or redundant session chrome such as duplicate chat connected pills and helper recent-invite history.
- Fixed installer upgrade/uninstall behavior when the bundled bridge `node.exe` is still running from the install directory.
- Hardened bridge shutdown on app exit and fixed bundled bridge dependency packaging.

## Notes

- Invite-based connect remains the primary flow.
- Helpee shares an invite with QR, share, and copy actions.
- Helper connects by pasting an invite or scanning a QR code.
- Phone QR scanner behavior still depends on the platform scanner app. If scanning does not offer a useful action, copy/paste remains the most reliable path.
