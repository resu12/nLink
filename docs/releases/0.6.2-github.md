# nLink 0.6.2

`0.6.2` is a file-transfer, approval-flow, and UX reliability release. It keeps H.264 screen sharing as the default from `0.6.0`.

## Highlights

- V4-only single-file transfer with explicit accept/decline before receive.
- Pause/resume controls for active inbound and outbound file transfers.
- Receiver-confirmed file-transfer progress.
- Downloads-folder saving by default, with automatic numbered names when a file already exists.
- Completed transfer pills can open the destination folder.
- Compact five-symbol handshake-derived session verification on approval screens; the fallback code remains internal and is not shown in normal UI.
- Hardened V4 file-transfer validation for data-frame source identity and oversized manifest chunk counts.
- File-transfer data is protected by nLink's session envelope and source/session validation rather than relying on NKN transport alone.
- File-transfer inbound data-session queues are bounded to `512` frames / `32 MiB`, and bridge binary payloads are capped before allocation.
- Better helper/helpee recovery when either side exits or times out during the accept/allow phase.
- Chat sending remains available during screen sharing.
- Advanced diagnostics labels the normal release transport as `NKN internet transport` and includes Balanced, High quality, and High performance screen-share presets.
- Windows taskbar/app icon is applied.

## Limits in 0.6.2

- Windows x64 only.
- Single-file transfer only.
- Inbound transfer requires explicit accept/decline.
- `25 GiB` default file-size cap.
- Pause/resume applies to the active in-session transfer and does not resume after app restart.
- Large file-transfer throughput and live screen-share delay can still depend on NKN/network delivery variance.
