# nLink 0.7.0 hotfix revision 2

**Draft — not published.** Proposed tag: `v0.7.0-hotfix.2`. The app and installer version remain **0.7.0**.

## Changes

- Establish Tuna in an approved idle screen-capable session before starting file transfer or screen sharing. Explicit payer unlock, authenticated negotiation and coordinator-owned file-route authority remain required.
- Re-establish idle Tuna after completed/canceled transfers, while rejecting stale stop, answer and ACK effects.
- Preserve the approved authenticated session during stale handshake cleanup, and bind listener startup, readiness, cap-stop and telemetry effects to their current owner.
- Keep lock/disable effective when accounting persistence fails, with truthful failure reporting and preserved observed payments. Treat rejected incoming streams as diagnostics, not a healthy listener's lifecycle state.
- Keep the session Tuna icon correctly colored during active or paused file transfers; it does not grant file-route authority.
- Invalidate pending wallet unlocks when locking, unlinking or replacing the wallet; terminate and reap canceled/timed-out wallet-verifier children.
- Show “Preparing helper address…” until the full verified address is ready, instead of briefly exposing the short bootstrap address.
- Keep Wallet status feedback visible below the scrolling options content.
- Make the recovery-keyframe test's bitmap-width poll safe during concurrent replacement/disposal; assertions and timeout remain unchanged.

## Status and limits

A connected lane is not proof of payload delivery or authority to publish a file route. No replay-window relaxation or throughput guarantee is claimed.
