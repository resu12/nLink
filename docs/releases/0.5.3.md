# nLink 0.5.3

`0.5.3` is the current public release after `0.5.2`. It keeps the same authenticated session and approval model, while simplifying the helper/helpee connection flow and rolling forward the latest session-lifecycle, invite-generation, transport, and file-transfer hardening work.

## Highlights

- Helper sharing is now centered on a helper address and short verification code instead of a manual invite handoff.
- Helpee can request help directly after entering or scanning the helper ID.
- Verification-code confirmation, explicit helper acceptance, and later capability consent boundaries remain in place.
- Repeated-session recovery after reject, timeout, remote end, and reconnect is substantially more robust than the initial `0.5.3` rollout state.

## Notable fixes in 0.5.3

- Helpee `Request help` now recovers more reliably after reject/end flows and invite regeneration.
- Helper timeout/reject recovery now returns to the main helper waiting flow instead of lingering on failure screens.
- Stale previous-session UI state such as old chat content or peer-ended notices is cleared more consistently on the next session.
- Screen-sharing and chat layouts were tightened so the chat pane stays more stable while typing and leaves more room for the shared screen.
- NKN file transfer now uses a more conservative startup profile to reduce repair churn on slower links.

## What stays the same

- Transfers are still single-file only in `0.5.3`.
- The app remains Windows x64 only.
- The default file-size cap remains `1 GiB`.
