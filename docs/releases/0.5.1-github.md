# nLink 0.5.1

`0.5.1` is the follow-up stabilization and hardening release after `0.5.0`.

## Important updates since 0.5.0

- Chat now uses the same session-secure transport envelope path as the other sensitive session traffic.
- Protected NKN seed storage is now the intended release path across supported desktop platforms; plaintext fallback is no longer part of the normal model.
- The local bridge hot path no longer uses JSON `payloadBase64` for large send/receive traffic; hot payload traffic now uses a framed binary stdio protocol.
- File transfer was hardened for reconnect handling, NKN bulk-path behavior, and post-`0.5.0` reliability stabilization.
- Diagnostics now state clearly that redaction is best-effort and include persistence/storage failure visibility.
- Privileged runtime actions now execute through a stricter internal authorization boundary.

## What stays in 0.5.1

- Native in-session file transfer remains inside the authenticated active session.
- Both helper and helpee can send a file during an active approved session.
- `Transfer files` remains a dedicated capability in the session approval model.
- Receiver-side saving still uses temp-first assembly, integrity verification, and safe finalize behavior with overwrite blocked by default.
- The release-default helper-bound invite and verified-helper flow remain unchanged.

## Limits in 0.5.1

- Single-file transfer only
- No folder transfer
- No drag-and-drop
- No resume after restart
- No multi-transfer queue
- File size cap: `256 MiB`
- Large transfers over NKN can still be slow

## Notes

- Invite-based connect remains the primary flow.
- Helper shares a helper address, then the helpee enters that helper address, confirms the verification code, and shares a helper-bound invite.
- Helper connects by pasting an invite code or scanning a QR code.
- Received files are saved under `%LOCALAPPDATA%\nLink\transfers\incoming\...` and are not auto-opened.
- Diagnostics export is best-effort redacted and should be reviewed before sharing.
