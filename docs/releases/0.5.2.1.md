# nLink 0.5.2.1

`0.5.2.1` is a focused stabilization release on top of `0.5.2`. It does not change the session protocol or approval model. This release fixes helper/helpee startup issues around local identity handling, removes stale local helper-target history, and tightens the public-invite bootstrap flow.

## Important updates since 0.5.2

- Helper address bootstrap now uses the active connected helper identity again, so helper-bound invites match the real joining identity.
- Helpee and helper startup now recover more safely when protected per-process NKN seed storage is unreadable.
- Startup now prunes stale `identity.instance-*.json` files and matching protected-seed sidecars for processes that are no longer running.
- Helper recent-address history has been removed; the helper connect flow now uses only the current pasted or scanned invite.
- Helper bootstrap failures now surface a clearer user-facing message when protected seed storage cannot be read.

## What stays the same

- Invite-based connect remains the primary flow.
- Helper-bound invites and verified-helper public invite flow remain the intended release path.
- Session protocol, capability checks, and security posture are unchanged.
- Native in-session file transfer remains single-file only and bound to the active authenticated session.
- Received files are still finalized only after integrity verification succeeds.

## Identity and Startup Behavior

- The app still keeps the shared local identity under `%LOCALAPPDATA%\\nLink\\identity.json`.
- Per-process identities are still used when needed for concurrent local app instances.
- Stale per-process identities are now cleaned up on startup before the current NKN key path is selected.
- Cleanup only targets `identity.instance-<pid>.json` files whose PID is no longer running.
- Custom configured NKN key paths are left untouched by the cleanup path.

## Limits in 0.5.2.1

- Single-file transfer only
- No folder transfer
- No drag-and-drop
- No resume after restart
- No multi-transfer queue
- File size cap: `256 MiB`
- Large transfers over NKN can still be slow

- If the helper address or invite was generated from an older broken build, regenerate both after updating.
- Diagnostics should now make protected-seed and startup-identity failures easier to spot.
