# nLink 0.6.0

`0.6.0` is the screen-sharing quality release. The headline change is that default screen sharing has moved from legacy JPEG frame updates to H.264 video transport, with new helper-side recovery and visual-integrity protection.

## Highlights

- Default screen sharing now uses H.264 video transport instead of JPEG frame-by-frame updates.
- Broken scrolling text and inter-frame artifacts are reduced through H.264 reference-chain quarantine, recovery followers, and motion-aware IDR/keyframe handling.
- Cursor movement is smoother through a helper-side cursor overlay, with captured cursor disabled where Windows Graphics Capture supports it.
- Helpee CPU use is reduced with upstream capture cadence, WGC GPU scaling, and direct same-size preprocessing.
- Windows 10 WGC teardown was hardened so the yellow capture border should disappear after sharing stops.
- Diagnostics now shows a support-focused view of connection, identity, screen-share health, cursor delivery, CPU/GPU capture state, and the latest screenshare evidence.

## Other improvements

- Helper address remains stable across restarts, with the short verification code restored on the helper screen.
- Added guarded helper-address regeneration for privacy resets.
- Added download-size versus installed-size packaging controls and package size summaries.
- Failed no-session screen-share soaks are now classified as setup failures instead of quality evidence.

## Limits in 0.6.0

- Windows x64 only.
- Single-file transfer only.
- `1 GiB` default file-size cap.
- Live screen-share delay can still depend on NKN/network delivery variance.
- The legacy JPEG decode path may remain for compatibility or fallback, but H.264 is the default screen-share path.
