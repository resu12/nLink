# nLink 0.5.2

`0.5.2` is the consolidated release after `0.5.1`. It includes the file-transfer throughput and protocol work that followed `0.5.1`, plus the later helper/helpee connect and startup fixes that were briefly tracked as `0.5.2.1`.

## Important updates since 0.5.1

- File transfer startup no longer waits on the initial offer hash; the sender now advertises the transfer first and prepares final metadata afterward.
- A new V3 streaming data-session path is available for updated peers, replacing the old small-batch request loop with receiver credit windows and continuous sender streaming.
- V3 transfer tuning now uses larger chunks and larger in-flight windows on healthy links, with stability-first clamp behavior under reorder pressure.
- Inbound file-transfer dispatch was split so lifecycle, control, and chunk work no longer serialize behind one queue.
- Helper/helpee identity bootstrap and invite binding were hardened so copied helper addresses match the real joining identity again.
- Protected per-process seed recovery and startup cleanup now recover or prune stale local identity artifacts more safely.
- Helper recent-address history has been removed to simplify the helper connect flow and avoid stale local target reuse.
- Transfer panel progress text was simplified to concise sending/receiving status.

## File Transfer

- Native in-session transfer remains part of the authenticated active session.
- The active path now prefers the newer metadata-first startup plus V3 streaming path when both peers support it.
- Healthy V3 transfers now use larger chunks and broader credit windows than `0.5.1`, while still keeping integrity verification and exact-size checks.
- Recovery is still explicit: repair requests, progress ACKs, and terminal fail/cancel paths remain visible in diagnostics and logs.
- Transfers are still single-file only in `0.5.2`.

## Connect and Identity Reliability

- Helper-bound invite bootstrap was corrected so invites match the actual connected helper identity.
- When protected per-process seed storage becomes unreadable, startup recovery is safer and less likely to wedge helper or helpee startup.
- Startup now prunes stale `identity.instance-*.json` files and associated protected-seed state for processes that are no longer running.
- Custom configured NKN key paths are still left untouched by the stale-cleanup path.
- Helper address history is no longer stored or reused locally.

## Security and Safety

- Session approval, capability checks, and invite security posture remain unchanged.
- File contents are still verified before a transfer is marked complete.
- Received files are still assembled through a temp-first flow and finalized only after byte-count and SHA-256 verification succeed.
- Received files are not auto-opened.
- Save behavior still blocks silent overwrite by default.

## Current Limits

- Single-file transfer only
- No folder transfer
- No drag-and-drop
- No resume after restart
- No multi-transfer queue
- File size cap: `1 GiB`
- Large transfers over NKN can still be slower than direct local-network copy

## Notes

- Invite-based connect remains the primary flow:
  - helper shares a helper address
  - helpee enters that helper address and confirms the verification code
  - helpee shares a helper-bound invite
  - helper connects by pasting an invite code or scanning a QR code
- After updating from older `0.5.2` pre-release/stabilization builds, regenerate the helper address and invite before retrying a failed connection.
- Release diagnostics should still report:
  - `invite_security_mode: issued_one_time_secret_invites`
  - `invite_public_flow: verified_helper_required`
  - `invite_security_release_ready: Yes`
  - `invite_security_warning: none`
- Current release assets live under `artifacts/releases/0.5.2/`.
