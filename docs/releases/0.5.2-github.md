# nLink 0.5.2

`0.5.2` is the combined post-`0.5.1` release. It includes the newer file-transfer protocol and throughput work, plus the later helper/helpee connect and identity-startup fixes that were temporarily tracked as `0.5.2.1`.

## Important updates since 0.5.1

- File transfer startup now sends the offer first and prepares authoritative metadata afterward.
- Added V3 streaming transfer mode for updated peers, using receiver credit windows and continuous sender streaming instead of the old small-batch request loop.
- Healthy V3 transfer now uses larger chunks and wider in-flight windows, with stability-first clamp behavior when reorder pressure rises.
- Split inbound file-transfer dispatch so lifecycle/control/chunk work is less prone to head-of-line blocking.
- Fixed helper identity bootstrap so helper-bound invites match the real joining helper again.
- Added safer recovery for unreadable protected per-process seed storage and startup cleanup for stale `identity.instance-*` artifacts.
- Removed helper recent-address history to simplify the connect flow and avoid stale local target reuse.
- Simplified transfer card copy to concise sending/receiving status.

## What stays the same

- Invite-based connect remains the primary flow.
- Helper-bound invites and verified-helper public invite flow remain the release-default path.
- Session protocol approval/security rules remain explicit and local.
- File transfer remains single-file only with a `256 MiB` size cap.
