# nLink 0.5.0

0.5.0 adds the first native nLink file transfer release.

## Highlights

- Native in-session file transfer replaces the older external tool flow.
- Both helper and helpee can send a file during an active approved session.
- `Transfer files` is a dedicated capability in the session approval model.
- Incoming files are accepted or declined per file, with visible progress, cancel support, and terminal success/failure state.
- File payloads are protected end-to-end and verified before success.

## Included improvements

- File transfer now runs inside the authenticated active session instead of leaving the nLink session shell.
- Receiver-side saving now uses temp-first assembly, integrity verification, and safe finalize behavior with overwrite blocked by default.
- File transfer state is shown in the chat/session panel on both helper and helpee sides.
- Diagnostics and logs now include file-transfer state and failure information for troubleshooting.
- The release-default helper-bound invite and verified-helper flow remain unchanged.

## Limits in 0.5.0

- Single-file transfer only
- No folder transfer
- No drag-and-drop
- No resume after restart
- No multi-transfer queue
- File size cap: `256 MiB`
- Large transfers over NKN can be slow

## Notes

- Invite-based connect remains the primary flow.
- Helper shares a helper address, then the helpee enters that helper address, confirms the verification code, and shares a helper-bound invite.
- Helper connects by pasting an invite code or scanning a QR code.
- Received files are saved under `%LOCALAPPDATA%\nLink\transfers\incoming\...` and are not auto-opened.
- Release diagnostics should show `invite_security_release_ready: Yes` and `invite_security_warning: none`.
- Current release assets live under `artifacts/releases/0.5.0/`.
