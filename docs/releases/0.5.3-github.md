# nLink 0.5.3

`0.5.3` keeps the `0.5.x` security model intact while simplifying how helpers and helpees connect and hardening the repeated-session lifecycle around reject, timeout, reconnect, and end-session flows.

## Highlights

- Helper shares a helper address and verification code instead of relying on a manual invite return path.
- Helpee can request help directly after entering or scanning the helper ID.
- Explicit helper acceptance and shared verification-code confirmation remain required before the session proceeds.
- Repeated-session recovery, invite preparation, and NKN capability stability are improved compared with the initial `0.5.3` builds.

## Notable fixes

- Fixed `Request help` getting stuck disabled after some reject/end flows.
- Fixed several helper/helpee stale-state issues after previous sessions, including old chat/status presentation leaking into new sessions.
- Improved helper timeout/reject recovery so passive helper flows return to waiting more reliably.
- Stabilized chat pane sizing and screen-sharing layout behavior.
- Reduced NKN file-transfer repair churn with a more conservative startup profile.

## Limits in 0.5.3

- Windows x64 only
- Single-file transfer only
- `1 GiB` default file-size cap
