# nLink 0.7.0

`0.7.0` keeps the H.264 screen-sharing path, V4-only file transfer, and normal NKN transport defaults from `0.6.2`. This release adds experimental NKN Tuna readiness work behind developer controls and a visible Diagnostics wallet-linking UX. Tuna is not enabled automatically and does not replace nLink's application-level session security.

## Highlights

- Diagnostics includes a new `Tuna (experimental)` wallet-linking section.
- Users can link a local `wallet.json`, validate balance with a session-only password prompt, copy the public wallet address, and unlink the wallet.
- Wallet linking stores only local state and public validation metadata; it never copies the wallet file and never persists the password, seed, private key, or decrypted wallet material.
- `nlink-tuna-sidecar` includes a safe `wallet-status` mode that validates a wallet and exits without starting a paid listener, dialing Tuna, or spending NKN.
- Tuna acceleration remains default-off and developer-gated through runtime flags.
- Tuna capability exchange is bound to the approved, verified nLink session and silently falls back to the current NKN transport on mismatch or sidecar failure.
- Phase 3 benchmark tooling compares current NKN and Tuna using file, screen, and reconnect profiles.

## File transfer and session security

- File transfer remains V4-only and single-file only.
- Inbound file transfer still requires explicit accept/decline.
- Active file transfers can be paused, resumed, or canceled from either side when file transfer is allowed for the session.
- File-transfer data is protected by nLink's session envelope and source/session validation; this release does not treat NKN transport alone or Tuna transport encryption as the security boundary.
- Existing file-transfer limits remain in place, including the `25 GiB` default file-size cap, `512` frame / `32 MiB` inbound data-session queue, and `64 KiB` bridge binary payload cap before allocation.

## Tuna experimental limits

- Tuna is not enabled unless developer runtime flags are set.
- Linking or validating a funded wallet does not start a Tuna listener, dial a peer, spend NKN, or change the default transport.
- Runtime acceleration remains limited to eligible screen media frames and file-transfer data frames after the normal nLink approval and verified session handshake.
- Chat, consent, handshake, remote control, screen control, and file-transfer control messages remain on the current NKN bridge.
- Product payment UX and installer packaging for the Tuna sidecar are still deferred.

## Screen sharing, chat, and shell UX

- H.264 screen sharing remains the default path.
- Advanced Diagnostics still exposes Balanced, High quality, and High performance screen-share presets.
- Chat input remains usable while screen sharing, including `Enter` to send and `Shift+Enter` for a new line.
- Normal release UX continues to use explicit helpee consent and session verification before allowing a session.

## Limits

- Windows x64 only.
- Single-file transfer only.
- Inbound transfer requires explicit accept/decline.
- File-transfer pause/resume applies to the active in-session transfer and does not resume after app restart.
- Large file-transfer throughput and live screen-share delay can still depend on NKN/network delivery variance.
- Tuna remains experimental and default-off.

## Support notes

For connection or approval issues, start with **Diagnostics -> Copy diagnostics** from both sides when possible. Diagnostics redacts Tuna wallet paths, wallet addresses, passwords, seeds, and private-key material from copied/exported support text.
