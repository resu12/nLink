# nLink 0.5.0

0.5.0 adds the first native nLink file transfer release. File transfer now lives inside the same authenticated session shell as chat, screen sharing, and remote control, with the same privacy-first approval model.

## Highlights

- Native in-session file transfer replaces the older external-tool flow.
- Both helper and helpee can send a file during an active approved session.
- File transfer is capability-gated with a dedicated `Transfer files` permission.
- Incoming files are accepted or declined per file, with visible progress, cancel support, and terminal success/failure state.
- File contents are protected end-to-end and verified before the transfer is marked complete.

## Native File Transfer

- Either side can click `Send file` once the active session grants `Transfer files`.
- Transfers are single-file only in `0.5.0`.
- The receiver sees file name and size before accepting.
- Progress is shown on both sides inside the existing chat/session panel.
- Transfers can be canceled by either side.
- File transfer stays bound to the active authenticated session and peer identity.

## Storage and Safety

- Received files are assembled through a temp-first flow and finalized only after byte-count and whole-file SHA-256 verification succeed.
- Received files are not auto-opened.
- Save behavior is safe by default and does not silently overwrite an existing file.
- The receiver writes into an app-owned folder under `%LOCALAPPDATA%\nLink\transfers\incoming\...`.
- `0.5.0` enforces a single-file size cap of `256 MiB`.

## Session Security and Diagnostics

- File transfer uses the existing authenticated active-session model rather than a detached external handoff.
- Release-default invite flow remains helper-bound issued-secret invites with verified helper confirmation.
- Diagnostics now include file-transfer summary state, failure code, active inbound/outbound transfer state, and saved-path information where relevant.
- Logs and diagnostics are improved for offer/accept/start/cancel/error/integrity/finalize troubleshooting without logging file contents.

## Current Limits

- Single-file transfer only
- No folder transfer
- No drag-and-drop
- No resume after restart
- No transfer queue
- Large file transfers over NKN can be noticeably slower than direct local-network copy

## Notes

- Invite-based connect remains the primary flow:
  - helper shares a helper address
  - helpee enters that helper address and confirms the verification code
  - helpee shares the invite with QR, share, and copy actions
  - helper connects by pasting an invite code or scanning a QR code
- Release diagnostics should report:
  - `invite_security_mode: issued_one_time_secret_invites`
  - `invite_public_flow: verified_helper_required`
  - `invite_security_release_ready: Yes`
  - `invite_security_warning: none`
- Current release assets live under `artifacts/releases/0.5.0/`.
