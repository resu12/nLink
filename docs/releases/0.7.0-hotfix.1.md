## Change and limits

The persistent software H.264 encoder now starts with CPU-memory NV12 input without first running the sink-writer input-buffer probe. The observed startup hang was inside the probe's MP4 finalization, before live frames could be encoded. Removing that prerequisite restores the primary encoding path without changing its input rejection, empty-output handling or fallback behavior.

This is not a general Media Foundation hang fix: the sink-writer fallback still uses its existing probe and finalization. Tuna route authority, capture permissions and transport policies are unchanged. Case 10323 remains paused.
