# nLink 0.6.0

`0.6.0` is the current public release after `0.5.3`. It keeps the helper-address and verification-code session model, and focuses on making screen sharing substantially more usable: the default screen-share pipeline has moved from legacy JPEG frame updates to H.264 video transport.

## Highlights

- Default screen sharing now uses H.264 video transport instead of JPEG frame-by-frame updates.
- Helper-side H.264 recovery protects the viewer from broken inter-frame text bands after loss, gaps, or recovery churn.
- Scrolling and fast motion are improved with motion-aware IDR/keyframe handling and stricter reference-chain safety.
- Cursor movement is smoother through a helper-side cursor overlay; captured cursor is disabled where Windows Graphics Capture supports it.
- Helpee CPU use is lower through upstream capture cadence, WGC GPU scaling, and direct same-size preprocessing.
- Windows 10 WGC teardown was hardened so the yellow capture border is closed with the capture session after sharing stops.

## Screen sharing changes since 0.5.3

- Migrated the default screen-share path from JPEG bitmap frames to H.264 transport frames.
- Added H.264 decode/recovery state, reference-taint tracking, protected recovery followers, and quiet-window quarantine release.
- Added motion detection and actual IDR proof so rapid scrolling can repair the H.264 reference chain faster.
- Added helper visual-integrity counters to retained soak artifacts and Diagnostics.
- Added high-quality helper-side interpolation when the received video is meaningfully upscaled or downscaled.
- Added a passive helper cursor overlay with cursor telemetry, latest-only delivery, and fallback to captured-video cursor when needed.

## CPU, teardown, and diagnostics

- Capture now skips ordinary raw frames before readback when they cannot be encoded at the active profile cadence.
- WGC can GPU-scale the captured texture to the active encode size before readback, avoiding full-size CPU resize on supported systems.
- Same-size BGRA frames use a direct NV12 conversion path.
- WGC stop now closes capture-session lifecycle objects on the owning apartment, which addresses the persistent yellow Windows 10 capture border seen after remote stop.
- Diagnostics was refreshed into a support-first view with connection, identity, screen-share health, cursor, CPU, GPU-scale, and latest operator verdict fields.
- Packaging now defaults to download-size optimization, with installed-size optimization available as an explicit build switch.

## Connection and identity

- Helper address remains stable across normal restarts because it is a public NKN identity, not an access secret.
- The short verification code is visible again once the active helper listener address is authoritative.
- A guarded `Regenerate helper address` action is available for privacy resets and invalidates older helper-bound addresses and invites.

## What stays the same

- The app remains Windows x64 only.
- Transfers are still single-file only.
- The default file-size cap remains `1 GiB`.
- Live screen-share delay can still depend on NKN/network delivery variance.
- The legacy JPEG decode path may remain for compatibility or fallback, but H.264 is the default screen-share path in this release.

## Support notes

If screen sharing is still poor on a specific network or PC, start with **Diagnostics -> Copy diagnostics**. For retained/live screen-share evidence, read `screenshare-operator-verdict.txt` first, then `quality-presentation-summary.txt`, then `low-fps-catch-up-summary.txt`.
