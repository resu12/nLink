# nLink 0.4.5

0.4.5 is the cumulative release after 0.4.2. It combines the recent screen-sharing work, invite/session security hardening, and the simplified helper/helpee connection flow into one release.

## Highlights

- Screen sharing is faster, clearer, and more stable under pressure.
- Helper-bound one-time invites are now the default release path.
- The helper/helpee bootstrap flow is simpler: helper shares a helper address, helpee shares an invite.
- Diagnostics, secret storage, and transport hardening were tightened for release readiness.

## Screen Sharing

- Lower-delay screen sharing with tighter pacing and better visibility into capture-to-send and capture-to-render timing.
- Clearer default text/UI on stable links, with higher-quality downscaling and less unnecessary shrinking.
- Better behavior under unstable links and after display changes, with fresher-frame delivery and explicit recovery-budget coverage.
- Added sender, transport, and viewer metrics for frame age, pacing, drops, and byte accounting.
- Screen-share send/receive paths now discard stale work more aggressively under pressure and after display mapping changes.
- Added automated resize/display-change recovery coverage with a defined render budget.

## Secure Session and Invite Flow

- Helper identity is now bound to the invite/session by default for the public release flow.
- One-time issued-secret invites replaced the old shared-secret invite trust model as the default path.
- Replay protection and post-handshake authentication were tightened for remote control, screen share, lifecycle traffic, and chat.
- Remote control execute-path authorization is enforced in runtime, not only in UI state.
- Legacy/insecure invite modes now require explicit internal opt-in and are not the normal release path.

## Simpler Helper/Helpee UX

- Helper now starts by sharing a helper address.
- Helpee enters that helper address, then shares a helper-bound invite.
- Helper connects by pasting the invite or scanning the QR code.
- The helper and helpee waiting screens were cleaned up to make the steps clearer and reduce unnecessary technical text.
- Helper and helpee sharing actions now support both copy and share flows.

## Diagnostics and Hardening

- Diagnostics now expose invite-security and transport-hardening state more clearly.
- Sensitive diagnostics export is more privacy-safe by default.
- Plaintext local NKN seed storage was replaced with protected local storage on Windows.
- Transport abuse-resistance now has stronger queue bounds, replay windows, and release-hardening diagnostics.

## Notes

- Invite-based connect remains the primary flow:
  - helper shares a helper address
  - helpee enters that helper address and confirms the verification code
  - helpee shares the invite with QR, share, and copy actions
  - helper connects by pasting an invite code or scanning a QR code
- Release diagnostics should report:
  - `invite_security_mode: issued_one_time_secret_invites`
  - `invite_public_flow: verified_helper_required`
  - `invite_security_release_ready: Yes`
  - `invite_security_warning: none`
- Current release assets live under `artifacts/releases/0.4.5/`.
