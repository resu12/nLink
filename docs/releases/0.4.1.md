# nLink 0.4.1

0.4.1 is a hardening release. It does not add a new product area; it improves the reliability, safety, and packaging quality of the existing remote-help flow introduced in 0.4.0.

## Highlights

- Remote control is more reliable across control start, stop, disconnect, reconnect, and session end.
- Helper and helpee UI now clear stale control/session state faster and explain important transitions more clearly.
- Installer, portable packaging, and bundled NKN bridge handling are more robust for real upgrades and shutdown.

## Stability and Safety

- Tightened request- and session-scoped remote-control handling so stale work is less likely to survive reset, reconnect, or control restart.
- Hardened disconnect and invalidation paths so active control and related state shut down more deterministically.
- Improved helper remote-control recovery so keyboard control can remain available when pointer mapping is temporarily unavailable, while mouse control regains mapping on active-control start.
- Added broader regression coverage around control ordering, reconnect churn, teardown, and repeated screen-share/control cycles.

## Performance and Responsiveness

- Coalesced replaceable control-state snapshots so they do not crowd out higher-value key/button input under load.
- Suppressed stale display-info sends earlier during stop/reset/restart churn to reduce wasted traffic and false handling.
- Re-baselined churn behavior with targeted tests for transport priority, queue-drop behavior, and repeated mixed control + screen-share cycles.

## UX and Diagnostics

- Clarified state wording for approval wait, connection progress, authorization loss, screen-change/mapping loss, and remote-ended sessions.
- Removed stale or redundant session chrome such as duplicate connected pills in chat and helper recent-invite history that no longer matched the invite model.
- Tightened helper and helpee affordances so disabled or unavailable actions clear faster on disconnect, reset, or invalidation.
- Improved operational diagnostics for stale input drops, stale snapshot drops, suppressed late display-info sends, and authorization-loss control stop.

## Installer and Packaging

- Fixed installer upgrade/uninstall behavior when the bundled bridge `node.exe` is still running from the install directory.
- Hardened bridge shutdown on app exit so the bundled bridge is less likely to remain orphaned after the app closes.
- Fixed portable/installer packaging so the bundled bridge ships with its required runtime dependencies.

## Notes

- Invite-based connect remains the primary flow:
  - helpee shares an invite with QR, share, and copy actions
  - helper connects by pasting an invite or scanning a QR code
- Phone QR scanner behavior still depends on the platform scanner app. If scanning does not give a useful action, copy/paste remains the most reliable path.
