# nLink 0.6.1

`0.6.1` is the current public release after `0.6.0`. It keeps H.264 screen sharing as the default path, and focuses on file-transfer reliability, approval-phase recovery, and clearer session verification.

## Highlights

- File transfer is shipped as V4-only, single-file transfer with explicit accept/decline before receive.
- Active file transfers can be paused, resumed, or canceled from either side when file transfer is allowed for the session.
- Sender progress now reflects receiver-confirmed transfer progress.
- Received files are saved to the Windows Downloads folder by default, with automatic numbered file names when the target already exists.
- Completed transfer pills can open the destination folder.
- Approval screens now show a compact five-symbol session verification sequence derived from the secure handshake; the text fallback remains internal and is not shown in the normal UI.
- Helper and helpee approval-phase recovery is stronger when the other side exits, times out, or leaves a stale request behind.
- Chat entry and sending remain available during screen sharing.

## File transfer changes since 0.6.0

- The active transfer implementation now uses the V4 data-frame path only.
- V4 data-frame source validation was tightened so control-lane setup frames and bulk-lane chunk frames are authenticated against the correct peer identity.
- File-transfer data is protected by nLink's session envelope and source/session validation; this release does not treat NKN transport alone as the security boundary.
- The inbound file-transfer data-session queue is bounded to `512` frames / `32 MiB` and fails closed with receiver-buffer-exhausted semantics under sustained unread floods.
- Bridge binary frames are capped before allocation, including a `64 KiB` payload cap.
- V4 manifest validation now caps chunk counts before receiver sparse tracking is allocated.
- Pause/resume is exposed in the sidebar transfer panel for active inbound and outbound transfers.
- Cancel remains available while paused and still uses the existing terminal transfer behavior.
- V4 sender/receiver progress and repair behavior were tightened so UI progress follows receiver acceptance more closely.
- File-transfer soak tooling, operator guidance, stabilization gates, and targeted V4 tests were added for release validation.
- The default save location is the user's Windows Downloads folder, and file-name collisions are resolved by appending a number before saving.

## Connection and approval

- Session verification now derives a compact five-symbol emoji sequence and internal fallback code from the handshake transcript.
- The helper and helpee approval UI uses a more uniform compact verification layout.
- Helper incoming-request handling has a timeout and background recovery when approval is not completed.
- Helpee and helper recovery paths were hardened so closing either side during the approval phase returns the other side to the correct starting state.
- Helper request admission was tightened to avoid accepting stale or mismatched requests.

## Screen sharing, chat, and shell UX

- H.264 screen sharing remains the default path introduced in `0.6.0`.
- Chat input remains usable while screen sharing, including `Enter` to send and `Shift+Enter` for a new line.
- The helper screen keeps a wider initial layout while the helper address loads.
- The Windows taskbar app icon is applied instead of the blank default app icon.

## Limits

- Windows x64 only.
- Single-file transfer only.
- Inbound transfer requires explicit accept/decline.
- The default file-size cap is `25 GiB`.
- File-transfer pause/resume is for active in-session transfers and does not resume after an app restart.
- Large file-transfer throughput and live screen-share delay can still depend on NKN/network delivery variance.

## Support notes

For connection or approval issues, start with **Diagnostics -> Copy diagnostics** from both sides when possible. For file-transfer investigations, include the transfer status messages and any file-transfer soak artifacts if they were captured.
