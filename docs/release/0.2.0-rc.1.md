# 0.2.0-rc.1 Release Process

Use this runbook when cutting `0.2.0-rc.1` from a frozen release candidate commit.

## Preflight

- Confirm the RC commit is frozen for release work only.
- Update `VERSION` to `0.2.0-rc.1`.
- Verify installer metadata picks up the same version.
- Confirm release notes draft is ready.

Run from the repo root on Windows:

```powershell
dotnet build .\nLink.sln -c Release
dotnet test .\tests\nLink.SmokeTests\nLink.SmokeTests.csproj -c Release --filter Category=Smoke
$env:NLINK_RUN_GUI_SMOKE='1'
$env:NLINK_GUI_SMOKE_SCENARIOS='HEADER_CHAT_COHERENCE,END_SESSION_DISABLES_CHAT,SCREENSHARE_BUTTON_VISIBILITY'
dotnet test .\tests\nLink.SmokeTests\nLink.SmokeTests.csproj -c Release --filter Category=GuiSmoke
Remove-Item Env:NLINK_GUI_SMOKE_SCENARIOS -ErrorAction SilentlyContinue
Remove-Item Env:NLINK_RUN_GUI_SMOKE -ErrorAction SilentlyContinue
powershell -ExecutionPolicy Bypass -File .\tools\PreRelease-Check.ps1 -RunGuiSmoke -GuiScenarios 'HEADER_CHAT_COHERENCE,END_SESSION_DISABLES_CHAT,SCREENSHARE_BUTTON_VISIBILITY' -RunBetaReadiness
```

Expected outcome:
- Release build passes.
- `Category=Smoke` passes.
- Windows GUI smoke passes for the RC scenarios above.
- `PreRelease-Check.ps1` completes and verifies release artifacts.

## Packaging

Build and verify the RC artifacts:

```powershell
powershell -ExecutionPolicy Bypass -File .\installer\Build-BridgeBundle.ps1 -Runtime win-x64
powershell -ExecutionPolicy Bypass -File .\installer\Build-Portable.ps1 -Runtime win-x64
powershell -ExecutionPolicy Bypass -File .\installer\Build-Installer.ps1 -Runtime win-x64
```

Expected outputs:
- `artifacts\releases\0.2.0-rc.1\nLink-Portable-win-x64-0.2.0-rc.1.zip`
- `artifacts\releases\0.2.0-rc.1\nLink-Setup-win-x64-0.2.0-rc.1.exe`
- `artifacts\releases\0.2.0-rc.1\SHA256SUMS.txt`

Packaging validation:
- `artifacts\portable\nLink\win-x64\bridge\win-x64` contains `index.js`, `node.exe`, and `node_modules`.
- `artifacts\portable\helper\win-x64\bridge\win-x64` contains `index.js`, `node.exe`, and `node_modules`.
- Release staging does not include debug-only payloads such as `*.pdb`, `*.xml`, or `Avalonia.Diagnostics.dll`.
- `SHA256SUMS.txt` matches the final installer and portable ZIP.

## RC Validation Checklist

- [ ] `VERSION` is `0.2.0-rc.1`.
- [ ] `dotnet build -c Release` passes.
- [ ] `dotnet test -c Release --filter Category=Smoke` passes.
- [ ] GUI smoke passes for `HEADER_CHAT_COHERENCE`, `END_SESSION_DISABLES_CHAT`, and `SCREENSHARE_BUTTON_VISIBILITY`.
- [ ] `tools\PreRelease-Check.ps1 -RunGuiSmoke -RunBetaReadiness` passes.
- [ ] Portable ZIP and installer are present under `artifacts\releases\0.2.0-rc.1`.
- [ ] Bridge runtime is bundled in both portable and installer staging folders.
- [ ] Checksums are generated and verified.
- [ ] Release staging has no debug-only dependencies.
- [ ] Release notes are ready at publish time.

## Go/No-Go

Go:
- [ ] All required smoke and GUI smoke checks are green.
- [ ] Packaging verification passed without missing bridge assets or debug-only release artifacts.
- [ ] RC artifacts, checksums, and release notes all match `0.2.0-rc.1`.

No-Go:
- [ ] Any smoke gate is red.
- [ ] Any packaged output is missing `bridge\win-x64`.
- [ ] Any release staging folder still contains debug-only dependencies.
- [ ] Artifact names, checksums, or notes do not match `0.2.0-rc.1`.

## Tag And Publish

```powershell
git tag v0.2.0-rc.1
git push origin v0.2.0-rc.1
```

Create a GitHub pre-release:
- Tag: `v0.2.0-rc.1`
- Title: `nLink 0.2.0-rc.1`
- Mark as pre-release

Attach:
- `artifacts\releases\0.2.0-rc.1\nLink-Setup-win-x64-0.2.0-rc.1.exe`
- `artifacts\releases\0.2.0-rc.1\nLink-Portable-win-x64-0.2.0-rc.1.zip`
- `artifacts\releases\0.2.0-rc.1\SHA256SUMS.txt`
