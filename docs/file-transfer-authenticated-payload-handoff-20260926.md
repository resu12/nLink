existing selected-native witness profile and refuses the old mixed terminal,
pre-verdict and selected-origin observer profiles. Ordinary production/default
loaders omit the new association API. Existing mixed-profile refusals remain.

existing protected log/source/destination owner, and duplicates those three

files and four collector outputs into the exact bound analyzer process.
Acknowledgement retires all parent copies before analysis proceeds; existing
write-exclusion checks verify that the child's adopted handles now protect the
files. Neither parent nor analyzer reopens payload paths to establish ownership.

The original source read, native writer EOF membership pass, selected failure,
witness preparation and three authority evaluations remain in place. The new
post-report association requires their exact current borrower, collector origin,
payload owner and publication completion. It compares the selected original
row's projected publication session/transfer tokens with the binding carried
inside the genuine protected-file handoff, and checks the producer's already
measured payload sizes and equal hashes. Diagnostic JSON is output only.

This adds two cumulative record visits: the existing selected-origin lookup and
one bounded selected-row scope check. The latter also accounts four times the
selected line's code units. The original work clock and 4096-visit, 20-second,
line/code-unit limits remain unchanged. There is no additional writer read,
payload hash, terminal scan, authority evaluation or budget reset.

A rejected admitted scope check remains spent. Disposing its non-owning result
does not dispose the borrower, original reader, publication completion or file
owners. Original context/worker cleanup invalidates the association and closes
the three producer files and four collector outputs.
